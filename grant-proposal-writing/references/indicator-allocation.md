# 指标分配与成果口径

用于从总项目指标中划分课题承担量，或核对成果承诺。用户已明确要求自行分配时，完成可审阅的建议分配，并回填本次负责内容；建议不能表述为指南原有分工或团队已批准方案。

## 1. 提取总要求

从当前指南和任务材料中区分数量总量、子集约束、性能阈值、唯一交付物和示范边界。明确本次规划总量，默认以要求的最低总量为基础；增加时说明依据及新增承诺。

## 2. 按职责分配

数量成果按技术职责与工作量分配。准确率、误差、响应时间等性能阈值，由对应责任内容承接，不能除以课题数。参与平台的数据或组件开发，不等于独立研制整个平台。

需要新增建议目标时，说明依据和建议属性。没有基线或测算依据，不编造收入、降本比例、伤亡减少比例等效益数值，也不由技术准确率直接推算经济效益。

## 3. 统一计数口径

- “其中”数量属于子集，不与总量重复相加。
- 共同成果按明确归属计一次；同一平台、点位或演练不能各课题分别计数。
- 区分申请与授权、发表与录用、提交软著申请与取得软著、标准草案与正式发布。
- 装备的“类”与“台”分别计量；数据样本明确有效性与去重口径，不把标签、增强裁片或共享数据重复计数。

## 4. 回填与核对

单独给出分配表，列明指标、总要求、各课题份额及合计或计数说明；共同成果需写清计数归属，必要时区分主责与协作。此处的归属说明不自动构成新的协作任务。

各份额合计应等于本次规划总量，并满足指南下限。正文只写对应责任范围的成果，按目标模板说明交付物、内容、功能和性能，不为每个组件凭空增加“1套”等数量。
