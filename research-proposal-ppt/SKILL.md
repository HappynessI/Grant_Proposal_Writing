# 横向项目与研究方案PPT制作

把分散的背景材料和团队素材整理成主线清楚、版式统一、内容可核实的汇报PPT。以下是默认做法，优先级从高到低为：用户本次要求、老师或规划方案的原话、用户指定的模板、本技能。

## 1. 明确任务

先读规划方案、当前稿件和素材目录，再提问。已经写明的信息直接采用，只问真正影响后续工作的事项：

- 报告讲给谁听，目的是什么：介绍单位整体研究、争取合作，还是汇报某项目方案？这决定页面主要讲技术还是主要讲效果。
- 本人负责哪些部分，每部分大约多少页？
- 要逐页方案，还是直接修改PPT？模板和当前稿件是哪一份？

规划方案要逐字阅读，老师的批注按原话执行。“直接复制”“可以不止6页”这类说法，先判断范围，再决定取舍。修改文件前重新读取磁盘上的当前版本，文件可能已被用户手动修改或改名，保留这些修改。

## 2. 按领域组织内容

报告按研究领域和技术方向组织，不按人组织。多位老师属于同一领域时，把他们的成果拆开，放进同一领域下的技术方向；领域只写一个背景。调换页面顺序和改关键句达不到这个效果，需要重新确定每页讲什么。

默认结构、页数分配和合并方法见 [references/content-rules.md](references/content-rules.md)。开始写页面前读这个文件。

## 3. 选择页面版式

大部分内容页由同一个骨架组成：标题，上方关键句横幅，中间两栏或三栏，下方结论横幅。讲一件事的多个特点且几乎没有图时，改用多行要点。

| 页面内容 | 默认版式 |
|---|---|
| 背景、需求、政策、场景等不涉及具体技术的内容 | 两栏，配现场图、文件截图或场景图 |
| 技术、方法、模型、算法 | 三栏，配论文方法图、结构图、结果图 |
| 已有或希望开展的应用 | 三栏，每栏先写一段说明，下方放图 |
| 两项并列的关键技术 | 两栏，每栏先写说明，下方放方法图和结果图 |
| 一件事的多个特点，几乎没有配图 | 多行要点，每行左侧写短标签，右侧写一句说明；有一张总图时放在右侧，没有时全宽排列 |

模板在 `assets/project-report-template.pptx`，共 13 页。每页的用途、形状编号和字数上限见 [references/page-layouts.md](references/page-layouts.md)。使用模板或复制页面前读这个文件。

同一个方向内部尽量沿用相同版式。用户给出参考截图时，按截图的结构调整，不沿用先前方案。除多行要点页外，每页都要有图，其他全是文字的页面要补图或换版式。多行要点页没有合适的图时不硬配。其他版式的图和说明上下排列，几乎不用左图右文。

## 4. 写页面文字

**关键句：** 一句有主语的完整陈述句，概括本页重点，避免口号。写满一行或写满两行，不留一行多一点的情况。模板关键句框一行约 41 个汉字，单行控制在 40 字以内。

**栏内要点：** 使用学术化的名词短语，三栏条数相同、长度接近，一般每条 8 字。

**栏内说明：** 写清对象、手段和效果。同一页三栏字数相差不超过 3 字，高度才能一致。

**多行要点：** 每页 3～5 行，超过 5 点时合并或分页。标签用相同字数的名词短语，一般 4 字；说明各写一句，长度接近。

**底部横幅和图注：** 横幅一句话收束本页，可以用“研究目标：”这类开头。图注只写图中确实展示的内容。

**字数：** 用脚本统计，不要目测。用户指定字数时严格满足，改完报告实际字数：

```bash
python scripts/check_deck.py --count "待统计的句子"
```

## 5. 选图

先看图再写字。每张图都要能支撑旁边的文字，判断时看图里实际画了什么，不看文件名或原页标题。图只展示研究基础时，文字也只写研究基础；不能把计划开展的研究写成已有成果。

技术页优先使用论文方法图、结构图和结果图。素材里只有视频或动图时，解压 `ppt/media` 后截取画面。合影、截图过宽或太小时，到原始网页查找高清原图。

每个小节的图片放在单独文件夹，文件名写明页面和内容。同一方向内不重复用图。放进页面前裁掉水印、错误标题和无关窗口，并保持比例。来自合作团队的素材，在图下用小字标注来源。

## 6. 核对事实和主体

每个数字、奖项、合作单位和排名都要能追溯到材料。说法超出材料时，先查证再写，例如“牵头”“首个”“获奖项目归属”。查不到就改写或请用户确认，并说明缺什么材料。

参考材料中的机构、模型和客户不能自动成为本次研究主体。“希望应用”和“已经应用”要分开写，设想页的图注写技术能力，不写成现场成果。用户要求去掉某内容时，直接删除并整理剩余内容，不写排除声明。

以下内容默认不放进页面：合同扫描件、涉军项目、个人联系方式。发现素材前后矛盾时，列出矛盾并请用户确认。

## 7. 交付

**逐页方案：** 每页给出标题、关键句（注明字数）、各栏内容、图片文件名和原始页码。配图保存到对应文件夹。不宣称已验证实际排版。

**直接修改PPT：** 按以下顺序进行。

1. 另存为新文件，不覆盖原文件。用 `scripts/inspect_deck.py` 读取页面和形状编号。
2. 写脚本调用 `scripts/deck_ops.py`，优先改已有页面或复制相近页面，继承原有样式。
3. 给每个改动页调用 `add_review_mark`，在左下角加审查标记。用户审查通过并要求删除后，运行 `deck_ops.py clear-marks`。
4. 运行 `scripts/check_deck.py`，并用 `scripts/preview_layout.py` 查看版面草图。草图的字体和颜色只是近似效果，脚本结果也是估算值。
5. 环境里有 PowerPoint 渲染能力时，用它检查实际页面。没有时说明未看过实际渲染，请用户打开检查，不要未经同意安装大型软件。
6. 目录中存在 `.~文件名.pptx` 表示文件正在 WPS 中打开。写入后提醒用户关闭时不要保存，否则旧内容会覆盖修改。

```bash
python scripts/inspect_deck.py 文件.pptx outline
python scripts/inspect_deck.py 文件.pptx shapes --pages 20-25
python scripts/inspect_deck.py 文件.pptx images --pages 3-9 --out 图片目录
python scripts/check_deck.py 文件.pptx --pages 20-37 --ban 旧客户名,老师姓名
python scripts/preview_layout.py 文件.pptx 20-25 预览目录
python scripts/deck_ops.py subset 文件.pptx 20-37 子集.pptx
python scripts/deck_ops.py clear-marks 文件.pptx
```

脚本依赖 `python-pptx` 和 `Pillow`。局部修改只处理指定页面及必要的相关内容。

## 8. 交付前检查

- **结构：** 是否按领域组织，同一领域是否只有一个背景，页数是否符合要求。
- **内容：** 数字和归属能否追溯，主体是否正确，图文是否对应，是否残留旧标题、旧客户名或上一页复制来的内容。
- **文字：** 关键句是否有主语并写满一行或两行，三栏长度是否接近。
- **版面：** 文字有无溢出，图片有无变形或过小，模块是否整齐，页码和编号是否连续。
- **文件：** 审查标记是否按用户要求保留或删除，原文件是否未被覆盖。
